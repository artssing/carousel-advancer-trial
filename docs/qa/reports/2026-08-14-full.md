## Outstanding

### MISMATCH [AN-03] analytics ingest now rejects malformed envelopes with 400 instead of swallowing them
- expected: `POST /analytics/events` with a malformed body (`{}` or `{"events":"nope"}`) → **201/200 + `{"accepted":0}`**, never an error status — analytics is fire-and-forget so a tagging mistake must not surface to the client (this is also the *stated design intent* written directly in `apps/api/src/analytics/dto.ts`'s own doc-comment: "this endpoint must never throw at a client — the ingest route swallows errors so a tagging mistake cannot break a user's flow")
- actual: both malformed bodies now return **400** `{"message":["events must be an array"],"error":"Bad Request","statusCode":400}`. The third malformed shape (`{"events":[{"event_name":"..."}]}` — valid array, bad element) still correctly returns `201 {"accepted":0}`.
- evidence:
  ```
  curl -s -X POST $API/analytics/events -H 'Content-Type: application/json' -d '{}'
  → {"message":["events must be an array"],"error":"Bad Request","statusCode":400}

  curl -s -X POST $API/analytics/events -H 'Content-Type: application/json' -d '{"events":"nope"}'
  → {"message":["events must be an array"],"error":"Bad Request","statusCode":400}

  curl -s -X POST $API/analytics/events -H 'Content-Type: application/json' -d '{"events":[{"event_name":"share_modal_opened"}]}'
  → {"accepted":0}   (this one still matches expected)
  ```
  Root cause (source-confirmed): `analytics.controller.ts:35` now types the body as `IngestEventsDto` (`@IsArray() events!`), and the global `ValidationPipe` (`whitelist`+`forbidNonWhitelisted`) only engages when the param is a class — which it now is. The pipe rejects before the handler's `body?.events ?? []` swallow-logic ever runs.
- Tag: **observed**
- scope last synced: `3b8dfcd` (11 commits behind HEAD `3fc5333`)
- Should the ingest route special-case a `ValidationPipe` exception filter so malformed envelopes still swallow to `{accepted:0}` (real bug — the DTO's own comment says this must never happen), or is a 400 on a badly-shaped envelope now acceptable and the case's expectation should change?
